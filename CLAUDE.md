## Project Overview

Enhanced Watermark Overlay Kit (EWOK) is a local Flask tool. Its main purpose is the **template designer** (`/template`): it designs wallpaper templates for JAWA's Brander, with text, QR, image and panel layers that use device variables (`{{device_name}}`, `{{serial_number}}`, `{{asset_tag}}`, `{{jss_id}}`, `{{location.building}}`, `{{role.*}}`, opt-in `{{user.*}}`). It previews live through `wallrender/` against sample devices, shows device crops and covered areas, supports role variants, and exports a `.brander.json` package or a `.zip` bundle. The **photo editor** (`/`) is the original tool: upload one image, adjust it, add text overlays (click to place), watermarks, image overlays and backgrounds, and resize it to wallpaper presets.

## Development Commands

```bash
# Install (Python 3.12+, uv); wallrender/ is installed editable alongside
uv sync

# Run: serves on http://127.0.0.1:5055 only (EWOK has no auth)
uv run ewok
# --open opens /template in the browser; EWOK_DEBUG=1 turns on Flask debug; --port or EWOK_PORT changes the port

# Run tests
uv run pytest
(cd wallrender && uv run --project .. pytest)

# Browser tests (tests/browser, headless Chromium; skipped without Playwright)
uv sync --group browser
uv run playwright install chromium
uv run pytest tests/browser
```

## Architecture

The app uses the Flask factory pattern with blueprints:

```
app.py                  # Entry point: the `ewok` command, calls create_app()
app_factory.py          # Factory: config, blueprints, local-only checks, cleanup hook
config.py               # Settings, canvas presets and their devices, sample devices, Brander variables
views/
  main.py               # Pages: / (photo editor) and /template (template designer)
  api.py                # Photo API: upload, process, download, preview (path traversal protection)
  template_api.py       # Template API: preview (wallrender, with contrast fixes), backdrop, device check and name fit, asset library, .zip and .brander.json export (sha256 header), import
utils/
  image_processing.py   # Photo editor: resize, text overlays, image overlays, backgrounds, watermarks
  cleanup.py            # Removes uploads and results an hour after last use (before_request hook)
templates/
  index.html            # Photo editor page
  template.html         # Template designer page
static/
  css/style.css         # EWOK names for roster tokens, Endor navbar, photo editor
  css/vendor/           # roster-web.css, roster-html.css, icons.svg (generated by roster-bridge)
  js/vendor/            # roster-theme.js (generated by roster-bridge)
  vendor/fontawesome/   # Font Awesome Free 6.0.0 solid CSS and webfont, copied unchanged (no CDN)
  css/template.css      # Template designer layout
  js/app.js             # Photo editor (IIFE, no inline handlers, live preview, click-to-place)
  js/template.js        # Template designer (layers, drag placement, devices, roles, draft)
wallrender/             # Renderer shared with JAWA (vendored, hash-pinned there); own pyproject and tests
  wallrender/schema.py      # Validation of untrusted templates (caps, roles, person_fields, QR rule, screen)
  wallrender/render.py      # Rendering and lint (missing values, glyphs, overflow, WCAG contrast)
  wallrender/devices.py     # device_profiles.json, crop and safe-area fit
  wallrender/roles.py, variables.py
  wallrender/cli.py         # `wallrender preview TEMPLATE VALUES -o OUT [--stress --devices IDS --strict]`, `wallrender devices`
tests/
  conftest.py           # Fixtures: isolated app with tmp_path dirs, test client, image helper
  test_*.py             # Photo API, template API, pages, foundation, isolation
  browser/              # Playwright tests of both pages (skipped without Playwright)
```

Data lives only in gitignored folders (`static/uploads/`, `temp/`, `template_assets/`). There is no database or external service. Views read the upload and temp folders from `current_app.config`, never from module-level copies.

### Key Patterns

- **Design: roster.** Both pages load the vendored roster files (`static/css/vendor/`, generated by roster-bridge; replace them with newer generated copies, never edit them) before `style.css`. `style.css` maps EWOK's `--color-*`, `--shadow-*` and font variables onto `--roster-*` tokens; panels are `rb-card`, messages and warnings `rb-alert`, counts `rb-badge`. The one colour of EWOK's own is Endor: the forest navbar (`#2f4a33`) with a treeline edge. No other hex in `style.css` or `template.css` (a test checks). Dark mode: `static/js/vendor/roster-theme.js` (in `<head>`, no `defer`) sets `.dark` on `<html>` from the saved `roster-theme` choice or the OS setting, the navbar button toggles it, and the `.dark` block in `style.css` remaps EWOK's variables (the preview checkerboard goes to roster gray 800/900). Status is never color alone: messages and toasts lead with a word, switches say On or Off.
- **Pillow pin:** `Pillow>=11.3,<12`, the same as JAWA. Text pixels differ between Pillow releases, so the preview only matches devices on the same version; change both repos together. Pillow 11.3 has published advisories (PSD, FITS, JPEG2000 and others, fixed in 12.x). They are not reachable: wallrender decodes only PNG and JPEG, and every `Image.open()` in EWOK passes `formats=` (`config.PHOTO_FORMATS` for the photo editor, PNG and JPEG for the asset library), so a PSD named `.png` is refused. Keep `formats=` on any new `Image.open()`. The move to Pillow 12 happens together with JAWA, with a new round-trip pixel fixture.
- **Local only:** no page requests anything outside 127.0.0.1 (a browser test fails on any other request). Icons are the vendored Font Awesome copy; use only `fas` names it defines (a test checks).
- **Accessibility checks:** browser tests inject axe-core from `axe-playwright-python`'s bundled copy (`test_template_fleet_stale_contrast.py`), so they stay offline. Out-of-date results are marked by words and a dashed frame, never by fading text. The preview re-renders on every keystroke pause, so its one live region is `#previewAnnounce`, which speaks only when the outcome changes; don't put `aria-live` on anything a render rewrites. A rebuild of the layer list or an overlay Delete puts focus back in the list (`focusRow()` in `template.js`, `removeRow()` in `app.js`).
- **Preview weight:** a render over an asset background previews as a JPEG (`PREVIEW_JPEG_QUALITY` in `views/template_api.py`; a full-size photo PNG is 8-12 MB); everything else stays PNG. Download preview posts to `/api/template/preview.png` for the lossless render, the same pixels as `wallrender preview`.
- **No framing:** an `after_request` hook in `app_factory.py` adds `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'` and `X-Content-Type-Options: nosniff` to every response. Inside a frame, a tricked click would be same-origin and pass `local_only()`.
- **Assets are never lost:** Delete moves an asset to `template_assets/.trash/`; a replace (upload or Open) moves the old copy to `.trash/replaced/`. Both wait a day, each copy under its own stamped name (`<id>.<stamp>.<ext>`), so a second replace or delete of the same id keeps the first. `POST /api/template/assets/<id>/restore` takes the newest copy and prefers the replaced slot (`?from=deleted` for Undo after Delete). Open answers 409 with `conflicts` when a template's asset differs from the library's under the same id, writes nothing, and the page asks before re-posting with `replace=yes` or `replace=no`.
- **Render cache:** every template API render passes `ASSET_CACHE` (a `wallrender.AssetCache` in `views/template_api.py`), so a device check or a preview after an edit reuses the decoded logo and its resized copy. It is keyed by a digest of the file's bytes, so a replaced asset never draws stale. New render calls should pass `cache=ASSET_CACHE` too.
- **Library thumbnails:** the asset list shows `GET /api/template/assets/<id>/thumb`, a 96 px JPEG (PNG when the asset has alpha) made once and kept in `template_assets/.thumbs/` under the original's mtime and size. Never point a list or picker `img` at the original: a 13-photo library was 30 MB per page load. Rendering, Download and the exports read the original.
- **Device check:** `FLEET_PARALLEL` (2) chunks of `FLEET_CHUNK` (10) are in flight at once, under one `AbortController`, so Stop, a newer check or a failed chunk cancels all of them.
- **Path safety:** All file-serving endpoints use `safe_filepath()` in `views/api.py` — `os.path.basename()` + `os.path.realpath()` containment check
- **Hex colors:** Validated via `hex_to_rgb()` in `utils/image_processing.py` — regex-based, returns `(0,0,0)` fallback
- **Font loading:** `load_font(size)` helper with system font fallback chain
- **Temp cleanup:** `utils/cleanup.py` runs via `before_request` hook — removes files older than 1 hour, at most every 5 minutes
- **SECRET_KEY:** Uses `$SECRET_KEY` env var; falls back to `secrets.token_hex(32)` with a DEBUG log (EWOK keeps no sessions)
